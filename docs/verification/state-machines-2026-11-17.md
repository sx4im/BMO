# Implicit state-machine inventory — 2026-11-17

This is a source audit of the current working tree, including concurrent stability
fixes. It catalogs stateful workflows, their terminal conditions, ownership, and
recovery contracts. It does not introduce a state-machine dependency or claim
that all possible runtime interleavings have been proven safe. Line references
identify definitions at audit time and may move as fixes land.

Method: read project context; use Graft map, exhaustive indexed searches for
state/timers/controllers/retries/threads, and targeted definitions; inspect the
source where graph excerpts omit transition details; cross-reference regression
test names. Coverage includes browser UI, backend request/background work,
cross-process cancellation, storage, deployment lifecycle, and WhatsApp. Pure
formatters, static components, and synchronous validation are not independent
machines. Transient menus and feedback are grouped where their contracts match.

In the tables, **end** names terminal states for one operation, not necessarily
the lifetime of the whole component. Tests name existing files under
`frontend/tests/` (F) or `backend/tests/` (B); coverage is specific to the listed
behavior, not a claim that every transition is tested. This audit itself did not
run suites, call paid models, modify production, or use microphone hardware.

## Priorities and actionable contracts

**Current stability work:** preserve partial/completed output across Stop and
save failure; make visibility/online reconciliation reachable; acknowledge a
committed row despite secondary timestamp/metering failure; recover bounded
checkpoint failures; propagate provider finish reasons/budgets and advance
frontend build identity. The parallel implementation and its verification record
own the final status of those changes; this document does not independently
declare them fixed.

**Next small fixes with high reliability value:** give route dispatch and each
stream run an ownership sequence; guard every callback/finalizer with it. Give
image generation a page-owned controller; serialize polling and reject stale
post-await results. Expand the reload busy predicate to actual user work and
unsaved input. Add deterministic tests that settle an older operation *after* a
newer one starts. These contracts address real ownership gaps with ordinary
JavaScript and focused tests.

**AX/UX:** render distinct generating, saving, unconfirmed, failed and retryable
states without removing the answer/actions. Announce state changes through one
appropriate status/alert region; preserve focus and keyboard controls when IDs
settle. Existing Customize progress and skill-listbox behavior are useful local
patterns. Avoid announcing every token/rotating phrase to screen readers. Audit
